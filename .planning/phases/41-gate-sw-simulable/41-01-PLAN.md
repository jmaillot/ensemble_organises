## Décisions de conception tranchées dans ce plan (pattern-mapper, réconciliées avec 41-RESEARCH.md)

1. **Routage du run e2e** : run séparé (comme la 39), routé par `testIgnore` sur la variable dédiée `E2E_SW_BASE_URL` — jamais le run standard. Le testIgnore actuel pose un piège : avec `E2E_BASE_URL` posé, `testIgnore: []` inclurait join-token-real dans le run sw-gate contre le serveur du harnais (où il n'a ni stack ni comptes). Le testIgnore devient une LISTE construite par condition — chaque spec réelle reste incluse uniquement dans SON run. Coût accepté : le run standard ne paie aucun des deux builds (plusieurs minutes) du run sw-gate. La spec tourne seule (`playwright test e2e/sw-gate-real.spec.ts`) avec `workers: 1` — la commutation du symlink est séquentielle, `fullyParallel` la rendrait flaky (Pitfall 4).
2. **Forme du harnais** (alignée RESEARCH §Harnais dev-only) : module dédié `app/src/lib/e2e-sw-harness.ts`, branché depuis `main.tsx` derrière la garde build-time `import.meta.env.VITE_E2E_SW_HARNESS === '1'` — le tree-shaking Rollup sur la constante d'environnement élimine l'import des builds qui ne posent pas le flag, et aucune chaîne de prod (compose.app.yaml, Dockerfile, build-app.sh) ne le pose : preuve exigée au Task 1 par grep sur le bundle du build standard (assumption A2). Exposition `window.__eoSwHarness = { buildId, ready(), injectOutboxPending(), clearOutbox() }` ; le harnais n'écrit QUE dans les sources existantes : `queryClient` exporté de `query-policy.ts` (la source unique D-03 de la file) et `useSessionStore`/`useHouseholdStore` via `getState()`. `sw-register.ts`, `use-outbox-gate.ts` et `update-banner.tsx` restent à diff nul — le branchement vit dans main.tsx, pas dans sw-register (la gate n'est pas ouverte pour ça).
3. **Deux dists servis sur le même origin** (alignée RESEARCH Approche A ; Approche D « interception Playwright » rejetée) : chaque build sort dans son répertoire (`--outDir dist-v1` / `dist-v2` via CLI Vite, build.outDir l.100 surchargé). Un serveur statique Node natif (`scripts/e2e-sw-server.mjs`, ~50 lignes, aucune dépendance) reproduit les 3 règles de `app/nginx.conf` (`Cache-Control: no-cache` sur tout, fallback SPA) et relit le symlink `dist-current` à CHAQUE requête — commutation à chaud sans coupure, Pitfall 6. **Pourquoi pas `page.route`** : GATE-01/SC1 exigent que le navigateur fasse sa revalidation RÉELLE de `/sw.js` contre des builds réels servis sur le même origin — l'interception ne prouve ni le cache HTTP ni le cycle install/waiting du SW, et Playwright rejouerait des octets qu'aucun serveur n'a servis (la recherche la classe « viole SC1 »). Le wrapper prouve le precache distinct par `diff dist-v1/sw.js dist-v2/sw.js` non vide AVANT de lancer la spec (§2.7 : le contrôle se prouve sur son entrée ; appui optionnel `scripts/check-precache-coverage.sh`).
