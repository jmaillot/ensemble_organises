# Milestone v1.2: Finition de la dette offline

**Status:** ✅ SHIPPED 2026-11-08
**Phases:** 36-37
**Total Plans:** 5

## Overview

Fermer les dernières fissures de la promesse offline de v1.1 — plus jamais d'effacement silencieux, un filet de tests fiable. Jalon volontairement 100 % dette/fiabilité : aucune nouvelle surface produit, hors les messages d'échec de l'outbox.

## Phases

### Phase 36: Outbox — plus jamais d'effacement silencieux

**Goal**: Toute écriture en outbox dont le rejeu échoue reçoit une classification explicite et un sort visible pour l'utilisateur — la décision 34 « jamais d'effacement silencieux » redevient vraie sans exception
**Depends on**: Nothing (première phase du jalon — la stack outbox v1.1 existe déjà)
**Requirements**: OBOX-01, OBOX-02
**Plans**: 2 plans

Plans:

- [x] 36-01-PLAN.md — Catalogue de libellés français (FAILURE_FAMILIES + failureLabel), scénario 404 rouge→vert, audit matriciel D-05 (OBOX-01, OBOX-02)
- [x] 36-02-PLAN.md — Retrait du toast D-12, badge unique signal actif, chaîne §2.7 complète (OBOX-01/D-03)

**Details (Success Criteria):**
  1. Un utilisateur écrit hors-ligne un élément supprimé entre-temps sur le serveur : à la reconnexion, l'entrée d'outbox n'est ni évaporée ni en boucle — classée terminale, message clair « cet élément a été supprimé entre-temps » (badge et panneau Paramètres cohérents)
  2. Chaque code d'erreur de rejeu (404, 400, 403 RLS, 42501, réseau, 5xx, …) couvert par un audit consigné avec sa classification terminal/retryable — aucun code ne laisse l'entrée disparaître ni rejouer indéfiniment
  3. Les échecs terminaux apparaissent dans le panneau avec l'action Abandonner (confirmation), les retryables restent rejouables via Réessayer — le badge « N en attente / N bloquées » reflète fidèlement chaque catégorie
  4. Des tests automatisés prouvent la classification des nouveaux codes (rouge→vert sur le scénario 404 silencieux d'origine) et la chaîne de vérification §2.7 reste verte

**Vérification**: 7/7 truths vérifiées (36-VERIFICATION.md).
