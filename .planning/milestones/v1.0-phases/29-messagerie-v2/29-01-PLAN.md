    1. `public.open_direct_conversation(p_other_member_id uuid) returns jsonb` :
       - Valider l'appelant (`auth.uid()` non null, modèle 0041:41) et résoudre son `household_members.id` ; valider que `p_other_member_id` est un membre ACTIF du MÊME foyer (refuser sinon, errcode 22023) — inclut les profils enfants gérés (phase 25), per D-04.
       - Verrou anti-course per la discrétion D-04/Pattern 1 : `perform pg_advisory_xact_lock()` sur un hash 64 bits de la paire triée (least/greatest des deux ids de household_members) — sérialise deux démarrages simultanés de la même paire.
       - Garde D-05 : chercher une conversation type 'direct' où le appelant ET l'autre membre ont chacun une ligne `conversation_members` avec `left_at is null` (participations actives). Per A1 du research : `archived_at is not null` NE compte PAS comme inactive — un fil archivé pour moi reste un fil qui existe et se rouvre (l'écriture désarchive via unarchive_on_send 0131). Tranchage explicite : rouvrir dès que `left_at is null` des deux côtés, per D-05.
       - Existante trouvée → `return jsonb_build_object('id', existante.id, 'created', false)`. Sinon → INSERT conversation (type 'direct', foyer du appelant, created_by appelant) + 2 lignes `conversation_members` (appelant + autre), `return jsonb_build_object('id', nouvelle.id, 'created', true)`.
    2. `public.conversation_read_receipts(p_conversation_id uuid) returns table(member_id uuid, display_name text, color_tag text, read_at timestamptz)` :
       - Vérifier que l'appelant est membre ACTIF (`left_at is null`) de `p_conversation_id` — sinon refuser (SQLSTATE '42501' ou raise exception), jamais de lecture globale (menace T-29-01).
       - Retourner, pour chaque co-membre ACTIF du fil, son watermark : jointure `public.conversation_members` → `public.household_members` (display_name, color_tag) LEFT JOIN `public.notification_reads` (scope 'conversation', scope_id = p_conversation_id, user_id du co-membre). Un co-membre sans ligne de watermark retourne `read_at NULL` (n'a pas lu — l'UI n'affichera que les non-null, D-02).
       - ATTENTION §2.7-A.5/D : dans le corps plpgsql, toute référence à `read_at`, `member_id` etc. est une variable — qualifier chaque colonne (`public.notification_reads.read_at`), le contrôle statique l'exige.
    3. `grant execute` des deux fonctions à `authenticated`.
    Aucune table nouvelle → aucune politique RLS nouvelle à écrire (notification_reads reste own-only, per la recommandation research). Ne JAMAIS réécrire 0041/0046/0101 — create or replace / create only dans 0171, correction vers l'avant.
