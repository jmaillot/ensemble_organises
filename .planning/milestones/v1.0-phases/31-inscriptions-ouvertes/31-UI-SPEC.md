# Phase 31 — UI Design Contract

> Visual and interaction contract for the Inscriptions ouvertes phase. Generated by gsd-ui-researcher from 31-CONTEXT.md (D-01…D-20), 31-SPEC.md (OUV-01…OUV-07) and the approved 25/29-UI-SPEC charte. Verified by gsd-ui-checker.

**Surfaces touchées (décisions D-14 à D-20 + SPEC req. 4/5/6) :**
1. `join-household-page.tsx` : devient le **pré-écran d'invitation dédié** (D-18) — un seul gabarit, deux actions (D-19) ; consultation du foyer via l'Edge preview (D-01/D-02, réponse minimale), token en sessionStorage avant inscription (D-06), réinjection au retour.
2. Traversée post-connexion : le même pré-écran affiche le bouton « Rejoindre » (D-08) ; trois messages dédiés au redeem authentifié (D-09/D-17).
3. `invitations-panel.tsx` **enrichi** (D-14) : défauts pré-remplis 30 j / 10, liste des tokens actifs **anonymisée** (D-15), révocation individuelle confirmée par modale (D-16).
4. **`/mentions-legales`** : nouvelle page publique (D-13), gabarit des pages `terms-page.tsx` / `privacy-page.tsx` existantes ; relecture langue claire du §conservation/suppression de `privacy-page.tsx` (l.179-193).
5. Emails de confirmation : FROM alias `contact@jeremymaillot.fr` (D-10) — hors DOM, aucune UI dédiée, prouvé par constat UAT (D-11).

**Aucune UI pour :** les middlewares Traefik 429 (réponse HTTP brute), les variables `RATE_LIMIT_*` GoTrue, l'exercice de restauration et la preuve push (preuves opérateur, pas des écrans), la migration invalidant les tokens existants (silencieuse ; l'admin voit simplement sa liste vide — cf. empty state du panneau).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn non initialisé — bibliothèque UI **first-party locale** : `app/src/components/ui/`) |
| Preset | not applicable |
| Component library | Radix UI (primitives sous `primitives.tsx`) + composants maison ; aucun ajout de dépendance |
| Icon library | Jeu d'icônes maison `@/components/shared/icon.tsx` (traits 1,8px, grille 24×24, `currentColor`) |
| Font | Display : Fraunces Variable (serif) · Corps : Inter Tight Variable |

**Aucun nouveau composant UI générique ne doit être créé dans cette phase.** La phase assemble les composants existants (Button, Field, Input, Dialog/ConfirmDialog, Panel, Toast, QrCode, EmptyState, Icon) dans les surfaces listées ci-dessus. Le pré-écran (D-18) est une **page**, pas un composant : gabarit `mx-auto max-w-[620px] place-items-center` du `join-household-page.tsx` existant, réutilisé tel quel. La page mentions légales suit le gabarit public de `terms-page.tsx`/`privacy-page.tsx` (même grille, même hiérarchie `eyebrow` → `h1` → `lede` → sections).

**Point focal par surface** — un seul élément primaire par écran, explicite : pré-écran = le titre d'invitation (h1 Fraunces, « Marie t'invite à rejoindre… ») suivi du CTA accent plein largeur ; panneau invitations = le bloc de génération (CTA « Générer ») ; mentions légales = le titre `h1` de page. Aucune action icône-seule dans la phase (chaque action porte son libellé), donc aucune exigence aria-label dédiée au-delà des patterns existants.

## Color

Charte existante (`app/src/styles/app.css`) — aucun nouveau token :

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` `#f2f0ec` | Fond de page (pré-écran, pages légales, panneau) |
| Secondary (30%) | `--color-surface` `#ffffff` | Cartes, Panel, encarts |
| Accent (10%) | `--color-accent` `#20413d` | CTA primaires (« Continuer vers l'inscription », « Rejoindre le foyer », « Générer un token »), focus-visible |
| Destructive | `--color-coral` `#d95f5c` (+ `coral-text`, `coral-soft`) | Révocation de token (bouton + modale), erreurs inline `role="alert"` |

Accent réservé à : boutons de confirmation primaires, focus-visible, encarts `bg-accent-faint border-accent/40` (gabarit existant « Pas de token sous la main ? »). **Jamais** pour les messages d'erreur token ni la révocation.

Sémantique spécifique à la phase :
- **Pré-écran token valide (D-02)** : le nom du foyer et le prénom de l'inviteur s'affichent en texte courant (lede, `text-fg`) — pas de couleur spéciale, pas de badge « invitation ». Chargement : Skeleton sur la ligne concernée.
- **Token mort en surface publique (D-03)** : message uniforme `text-coral-text` 11px sous le gabarit d'erreur existant — la réponse Edge porte le même code HTTP et le même message quel que soit le motif, l'UI ne nuance jamais.
- **Liste des tokens actifs (D-15)** : date de création, expiration, compteur « N / M utilisations », statut — texte dense 13px, jamais le token brut. Le brut ne s'affiche qu'une fois, dans le bloc de rappel existant à la génération (décision verrouillée AGENTS.md §2.5).
