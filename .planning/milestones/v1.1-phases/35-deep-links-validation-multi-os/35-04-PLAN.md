<objective>
Fermer les DEUX gaps de 35-VERIFICATION.md par une cause racine commune : le bootstrap d'authentification n'est pas tolérant au hors-ligne, donc le routeur ne monte jamais — ni la vue /taches/jour depuis le cache (§1.4), ni l'écran « connexion requise » (§1.5).

Cause racine tracée dans le code réel : `Root()` → `useAuthBootstrap()` → `applySession(session.user)` → `store.signIn()` → `loadHousehold()` (session-store.ts:158) fait des lectures réseau (`data.list('household_members')`, `data.list('households')`) qui rejettent hors-ligne ; le rejet remonte à `fail()` (use-auth.ts:167) → écran WR-04 au lieu de `<AppRouter />`. Les gardes du routeur (RequireAuth, D-07 dans sign-in-page.tsx:141) ne sont jamais atteintes — le correctif est donc DANS le bootstrap, pas dans l'ordre des gardes.

Direction du correctif (décision de conception, ce plan) :
1. `loadHousehold()` devient tolérant hors-ligne : si les lectures réseau rejettent alors que `onlineManager.getOnline()` est false ET que le foyer est déjà persisté dans household-store (`householdId` non null + `members` non vide, restauré synchro par le persist zustand), on garde le foyer persisté, on marque `householdLoaded` et on résout — la revalidation serveur se fera au retour du réseau. Sans foyer persisté OU en ligne : le rejet se propage (WR-04 préservé).
2. Le bootstrap Supabase (use-auth.ts) gère le rejet hors-ligne de `getSession()`/rafraîchissement : si la chaîne rejette alors que l'app est hors-ligne, on passe par le chemin invité (purge locale best-effort + `setReady(true)`) au lieu de l'écran d'erreur — le routeur monte, RequireAuth redirige vers /connexion avec `state.from`, et l'écran D-07 apparaît sur un deep link.
3. Une session dont `expires_at` est dépassé et hors-ligne ne doit JAMAIS être appliquée comme authentifiée : elle tombe sur le chemin invité (T-35-06).

Purpose: Les SC1/SC2 du roadmap sont contredits sur appareil réel (2 OS) par un défaut invisible aux tests actuels — aucun test automatisé n'exerçait le cold-start hors-ligne. Ce plan corrige ET ajoute la couverture automatisée du chemin réel.
Output: Bootstrap tolérant hors-ligne, tests unitaires des branches hors-ligne, cas e2e hors-ligne ; les deux gaps mécaniquement fermés (la re-validation on-device humaine est le plan 35-05).
</objective>
