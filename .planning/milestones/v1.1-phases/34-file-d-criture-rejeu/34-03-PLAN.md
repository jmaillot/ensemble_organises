## Interprétation explicite de D-10 (déviation mécanique, décision verbatim)
D-10 verbatim dit « terminal → surfacé à l'utilisateur, **retiré de la file**, jamais rejoué ». Ce plan substitue « retiré de la file » par « conservé en file avec `status: 'failed'`, jamais rejoué automatiquement ; retrait réel UNIQUEMENT via l'action utilisateur Abandonner du panneau (plan 04, confirm-dialog) ». Raison documentée : retrait automatique immédiat = effacement silencieux du refus, ce que D-11/D-12 (surfacage et action) exigent de rendre visible et actionnable d'abord. La PROPRIÉTÉ verbatim de D-10 — « jamais de retry en boucle, jamais d'effacement silencieux » — est intégralement tenue (test de non-boucle Task 2) ; le retrait verbatim est délégué à l'utilisateur, trace visible conservée entre-temps. Cette substitution est le mécanisme derrière Réessayer/Abandonner (D-11), pas un amoindrissement de portée. De même, D-16 (rapprochement par clé client au row Realtime) est substitué par identité + invalidation per RESEARCH A3 — le canal Realtime n'expose pas les rows au client : le create rejoué porte déjà id+client_key côté client (plan 02), donc le row serveur remplace l'overlay sans permutation d'identifiant, et l'invalidation (succès + Realtime existante) fait primer le serveur ; les propriétés de résultat D-16 (serveur prime, pas de doublon, pas de flash d'ancien état) sont testées telles quelles.
