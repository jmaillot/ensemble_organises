## Copywriting Contract

Copies en français, ton existant de l'app (phrases courtes, honnêteté explicite, aucune promesse de fraîcheur).

| Element | Copy |
|---------|------|
| Primary CTA | Aucun CTA sur le bandeau stale — il est informatif, non-actionnable, non-dismissable (il se retire tout seul au retour du réseau, D-13). Pas de bouton « Plus tard » : masquer l'horodatage reviendrait à présenter la donnée comme fraîche. |
| Bandeau stale (OFFR-02) | `Dernier état connu le {horodatage}` — horodatage formaté `date-fns` : `format(date, "d MMM 'à' HH:mm", { locale: fr })`, ex. « Dernier état connu le 4 nov. à 16:35 ». Jamais de « à jour », jamais d'horodatage relatif flou (« il y a 2 h ») : la date absolue est la plus honnête. |
| État vide honnête (D-09, maxAge dépassé hors ligne) | Title : `Données non disponibles hors ligne` — Description : `Les dernières données connues ont plus de {maxAge lisible} ; par honnêteté, elles ne sont pas affichées. Rétablissez la connexion pour les charger.` Rendu via `EmptyState` existant (icône `wifi-off` si présente dans `IconName`, sinon `heart`). |
| Error state (OFFR-03, hors allowlist) | INCHANGÉ — l'erreur d'origine des modules hors allowlist reste exactement ce qu'elle est aujourd'hui (`networkMode: 'always'` → `ErrorState`). Aucune nouvelle copie, aucune régression. |
| Destructive confirmation | Aucune action destructive nouvelle. La purge de déconnexion (D-05) échoue → toast d'erreur existant (`toast.tsx`) : `Impossible de vider les données locales : la déconnexion est bloquée pour protéger vos données. Réessayez.` |

Interaction avec le `OfflineBanner` existant : hors ligne, l'utilisateur voit DEUX bandeaux empilés — le bandeau corail global (inchangé, il couvre les pages sans cache Tier 1) puis, dans le slot bannières, le bandeau ambre horodaté (précision sur les données Tier 1 rendues depuis le cache). Ne pas fusionner les deux dans cette phase : le corail porte des pages entières, l'ambre porte une fraîcheur datée. La fusion est notée comme idée v1.x.

## Annex — Interactions verrouillées (de CONTEXT.md)

- **D-11** : un seul bandeau global, dans le slot `banner-store` — jamais de bandeau inline par vue.
- **D-12** : horodatage = MIN des `dataUpdatedAt` de **toutes** les `queries Tier 1 rendues depuis le cache`, **annexes `household_members`/`profiles` comprises** (D-10 les fait Tier 1) — une version antérieure de cette ligne excluait les annexes du MIN ; révoqué en révision de plan : l'exclusion n'a jamais été approuvée par l'utilisateur (33-DISCUSSION-LOG ne l'enregistre pas) et rendrait l'horodatage plus flatteur, à l'encontre de l'intention D-12 (« jamais la plus flatteuse »).
- **D-13** : visible uniquement hors ligne (`useOnlineStatus`) ; en ligne, jamais de bandeau.
- **Pitfall 2 (RESEARCH.md)** : le critère de rendu des modules Tier 1 est « `data` présente ? » → données + bandeau ; sinon `isError` → `ErrorState`. Jamais les deux à la fois, jamais l'inverse.
- Valeur de priorité : `sw-update` = 1, `install` = 2 (lus dans `sw-register.ts` / `install-banner.tsx`) → `offline-stale` = **3**.
