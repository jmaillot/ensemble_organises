# Milestone v1.4 — Preuve & décision

**Jalon :** v1.4 « Preuve & décision » — fermer les deux dettes priorisées de v1.3 : la surface bridge ardoise devient prouvée en production réelle, et la décision de cache maxAge est tranchée famille par famille avec les données on-device. Aucune nouvelle surface produit.

## Requirements (v1.4)

### Preuve bridge ardoise (W1)

- [x] **PROOF-01** : Un script sœur `scripts/test-ardoise-bridge-real.sh` (convention du dépôt : un script par preuve à ressource réelle, pas d'extension inline de `test-join-token-real.sh`) prouve le happy path du bridge ardoise sur le fil HTTP réel : Edge `ardoise-invite` action `household-token` → RPC `create_household_bridge_token` (service_role) → redeem 0181 — chaque étape avec preuve HTTP attribuable (méthode, statut, champs clés, estampille du build déployé), jamais SQL seul (§2.7 A : la preuve traverse le chemin complet)
- [x] **PROOF-02** : Le script inclut ≥ 3 négatifs red-team sur le vrai fil (replay du token consommé, token forgé/muté HMAC, token expiré ou cross-household), chacun prouvé rouge avant d'être vert — refuser un négatif sans le fil serait prouver la mauvaise couche
- [x] **PROOF-03** : La réconciliation des participations (`invite:` → `membre:`) est prouvée par lecture d'état après coup bornée par foyer — participations converties sans duplication ni orphelin — et le refus de ré-redemption (single-use) est un assert positif du script
- [x] **PROOF-04** : Le script suit la discipline secrets/attribution du dépôt : secrets uniquement via `curl -K` fichier 0600 (jamais argv/env), comptes e2e via `lib-smoke-accounts.sh` avec purge vérifiée (re-delete → 404), foyer éphémère créé et purgé par le script, attribution net._http_response capturée avant l'appel (patron test-dispatch-push)
- [x] **PROOF-05** : Une preuve de consignation datée est écrite dans `docs/` (forme 38-E2E-SIGNATURE.md) : ce qui est prouvé, ce qui ne l'est pas, verdict de chaque étape — jamais un succès muet
- [x] **PROOF-06** : Le script est idempotent avec teardown automatique (réexécutable après un déploiement sans accumulation d'artifacts)
- [x] **PROOF-07** : Si le script révèle un seam client suspecté (CORS, redirect, copy), un e2e navigateur réel du parcours invité est ajouté — déclenché par besoin, jamais préventif

### Décision cache maxAge (CACHE-01)

- [x] **CACHE-01** : Le maxAge est tranché famille par famille selon les critères §5 contraignants de `docs/MESURES-COLD-START-42.md`, avec la campagne on-device prescrite par §6 (appareil de référence, purge froide comparable §2.1, N=5 runs ou différé honnêtement consigné — jamais l'émulateur, jamais de valeur inventée) ; la lecture du panneau précède toute décision (les critères b/c décident, la lecture a seule jamais — biais d'ordre) ; un statu quo justifié est une décision valide
- [x] **CACHE-02** : Au plus un commit par famille modifiée d'`OFFLINE_FAMILIES` dans `query-policy.ts` : valeur + Test H vert + commentaire dans le même commit ; `gcTime` (7 j) reste ≥ au maxAge le plus long ; l'outbox, le bandeau offline (MIN dataUpdatedAt) et le SW restent intouchables (anti-features verrouillées v1.1/v1.3)
- [x] **CACHE-03** : La décision est consignée dans PROJECT.md (valeur + justification par famille) et la grille §7.4 du protocole est remplie avant toute édition de code
- [x] **CACHE-04** : Si l'observabilité avant/après devient nécessaire pour trancher, un détail cache par famille en lecture seule est ajouté au panneau diagnostic — déclenché par besoin, jamais préventif

## Out of Scope

- **Environnement de staging** : la preuve est prod (décision continue du projet) ; un staging introduirait un deuxième système à maintenir pour un verdict moins attribuable
- **Négatifs red-team en SQL seul** : la classe de vulnérabilité est invisible sous le fil HTTP (§2.7 A)
- **Foyer de test partagé persistant en prod** : foyer éphémère créé et purgé par le script
- **Interrupteur global maxAge (24 h / 7 j unique)** : CA-01 — l'arbitrage est par famille, c'est l'objet même de CACHE-01
- **Toute décision touchant l'outbox** (purge indépendante du maxAge, verrouillée v1.3), le bandeau offline ou le SW (invariant v1.1 : jamais de cache API dans le SW)
- **Adoption d'`experimental_createQueryPersister`** : casserait l'outbox, le namespacing D-03 et le throttle muté (recherche STACK, Context7 vérifié)
- **GATE-01 dans une phase** : reste un observatoire (re-test au prochain déploiement naturel), Pitfall 13
- **Nouvelle surface produit** : le jalon est 100 % dette/fiabilité
