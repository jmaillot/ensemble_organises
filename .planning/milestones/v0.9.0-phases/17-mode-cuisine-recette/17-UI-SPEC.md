Notes (prescriptive):

- Only 2 weights in this phase: 400 + 700.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(98% 0.004 240)` (`--color-bg`) | Page background |
| Secondary (30%) | `oklch(100% 0 0)` (`--color-surface`) | Panel surface, sticky header background (`bg-surface/95` + backdrop-blur) |
| Accent (10%) | `oklch(56% 0.12 170)` (`--color-accent`) + `--color-accent-strong` / `--color-accent-soft` / `--color-accent-faint` | Reserved elements only (see list) |
| Destructive | `oklch(64% 0.15 32)` (`--color-coral`) | Final « Réinitialiser » confirm button only |

Accent reserved for: (1) pastille XL number circles (`bg-accent-soft`, numeral `text-accent-strong`) — static, non-interactive; (2) progress bar fill (`bg-accent` on `bg-accent-faint` track, reuse `Progress` primitive as-is); (3) toggle `Switch` checked track (`data-[state=checked]:bg-accent`); (4) checked `Checkbox` fill (`data-[state=checked]:bg-accent-strong`). Nothing else in this phase uses accent — reset buttons use `secondary` variant, fallback mention uses `text-muted`, connector line uses `bg-border`.

Checked step text: `text-muted` (no strikethrough — D-02 forbids barré-sur-place; collapse + mute instead).

Focus: existing global `:focus-visible` (3px `accent-strong` outline, 3px offset) — unchanged, applies to toggle, checkboxes, reset buttons.

| Element | Copy |

| Panel description OFF | « Glissez la pastille numérotée pour réordonner. » (existing, unchanged) |

| Counter | « N/M » (e.g. « 2/3 »), `aria-live="polite"`, progress `aria-label` « Progression : N étapes sur M » |
| Wake-lock fallback | « Veille non bloquée sur cet appareil. » (14px `text-muted`, directly under the progress bar, rendered only when Wake Lock unsupported; never an error) |
| Reset (header, subtle) | Link-button « Réinitialiser » (14px, `variant="quiet"`, right of counter in sticky header) |
| Reset (bottom, explicit) | Button « Tout réinitialiser » (`variant="secondary"`, full-width on mobile, after last step) |
| Destructive confirmation | Inline (no modal — no server data at stake, D-14): « Tout effacer ? » + « Annuler » (`secondary`) / « Réinitialiser » (`danger`, coral). Replaces the reset button in place; « Annuler » restores it. |
| Empty state heading | « Aucune étape pour l'instant. » (existing `RecipeSteps` copy, reused verbatim in cuisine view when `steps` is empty; toggle still renders and stays operable) |
| Empty state body | None — single-line state, no CTA (steps are added in edit mode, not in cuisine view) |
| Error state | None rendered. localStorage unreadable/full → progress silently session-only (no toast, no banner — cooking must never be interrupted). Wake Lock request rejected → silent (mode continues, checkboxes work); fallback mention appears only for unsupported browsers. |
| Step checkbox label | « Marquer l'étape N comme faite » (existing pattern, N = visible number) |
| Completion state | Counter « M/M » + bar full; no extra copy, no confetti, rows stay collapsed |

## UI Considerations

Applicable state considerations resolved: 9 covered, 1 backstop, 0 unresolved · 13 dismissed as not-applicable (reason recorded, never silent).

Primary visual anchor in cuisine view: sticky header counter + bar; secondary anchor: pastille XL numbers.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | cuisine step list (0 steps) | ✅ covered | Renders the documented « Aucune étape pour l'instant. » copy, counter hidden, reset hidden |
| populated | cuisine step list (unchecked steps) | ✅ covered | Each row: 48px pastille XL + 18px text + left 48px checkbox, connector kept except after last |
| partial | counter + bar (0 < N < M) | ✅ covered | Counter « N/M » announces politely per toggle, bar at N/M via Progress primitive |
| partial | sticky header counter states (0/N, N/M, M/M) | ✅ covered | « 0/N » initial, « N/M » in progress, « M/M » + full bar at completion; no extra copy at M/M |
| populated | all-checked (N = M, M ≥ 1) | ✅ covered | Counter « M/M », bar full, all rows collapsed to 14px muted 2-line clamp |
| zero-one-many | single-step recipe (M = 1) | ✅ covered | Counter « 0/1 » then « 1/1 », reset present, layout identical |
| long-text | step content > 3 lines | ✅ covered | Unchecked row grows to full text, never truncated; checked row clamps to 2 lines with full text kept in aria-label |
| long-text | toggle / reset / counter / fallback labels | ✅ covered | Fixed short copy (« Mode cuisine », « Réinitialiser », « Tout réinitialiser », « N/M ») — never grows past one line |
| overflow | sticky header over long lists | ✅ covered | Header (counter + bar + fallback + header reset) sticks to panel top with surface-blur background while steps scroll beneath |
| partial | localStorage unavailable or quota-exceeded | 🧪 backstop | { statement: checkboxes remain fully operable session-only with no error UI, verification: backstop } |
| loading | toggle, step list, header, reset, wake-lock | ➖ dismissed | No async load in this phase: cuisine view renders synchronously from already-loaded `steps` (zero PostgREST, SPEC R3/R5) — nothing to skeletonize |
| error | toggle, step list, header, reset, wake-lock | ➖ dismissed | No error UI by locked design: localStorage failure → silent session-only, Wake Lock rejection → silent continuation (Copywriting Contract error row) — cooking is never interrupted |

Toggle interaction contract (both `recette-detail-page.tsx` « Étapes » panel and `guest-recipe-page.tsx` steps panel):
- Toggle = single tab stop: `<button type="button" aria-pressed>` containing visible 14px/700 label « Mode cuisine » + `Switch` visual (`tabIndex={-1}`, `aria-hidden`). OFF by default on every open (mode never persisted; only checked ids are stored under `eo:recette:cuisine:<recipeId>`).
- ON → cuisine view replaces `RecipeSteps`; OFF → edit view returns with identical draft/edit state; toggling never scrolls (D-13: scroll/focus preserved via stable panel anchor, no `scrollTo`, no autofocus).
- Wake Lock: requested on toggle-ON when `navigator.wakeLock` exists; released on toggle-OFF, sheet close, and unmount; re-acquired on `visibilitychange` → visible while ON. No separate switch, button, or checkbox anywhere (R4 amendment).
- Child role and guest page: identical toggle + cuisine view; zero edit affordances in ON state (no add form, no drag, no move/edit/delete buttons); guest path issues zero PostgREST calls (reads already-loaded `steps`).
