Étendre le contrat `DataAdapter` d'une option explicite, puis la faire appliquer par les deux implémentations et prouver un seul chemin jusqu'à un consommateur réel.

Dans `app/src/lib/data/adapter.ts` : exporter `RemoveOptions = { ifMissing?: 'error' | 'ignore' }`, documenté — sous RLS, une politique `for delete using (...)` exige la **visibilité** de la ligne ; zéro ligne supprimée signifie donc « la politique a refusé » ou « la ligne n'existe plus », deux cas qui doivent remonter plutôt que mentir. Le défaut est `'error'`. Changer les signatures en `remove(table: string, id: string, options?: RemoveOptions): Promise<void>` et `removeWhere(table: string, filter: RowFilter, options?: RemoveOptions): Promise<void>` (D-02).

Dans `app/src/lib/data/supabase-adapter.ts` : sur `remove` (lignes 135-139), remplacer la suppression muette par une suppression qui demande les lignes retirées — `.delete().eq('id', id).select()` — puis compter : si `error`, lever `DataError(error.message, error)` ; si la liste rendue est vide **et** que `options.ifMissing` n'est pas `'ignore'`, lever un `DataError` dont le message est lisible par l'utilisateur (« Suppression refusée : la ligne n'existe plus ou votre rôle ne le permet pas. »), avec un `cause` portant la table et l'`id`. Même traitement sur `removeWhere` (lignes 142-153), avec `.select()` sans nom de colonne : la table peut ne pas porter d'`id` (jointures), et un `select('id')` y échouerait. Ne PAS demander `count: 'exact'` : c'est la représentation qui compte, et une seconde requête de comptage serait une fenêtre de course. Conserver le style d'itération de filtre existant.

Dans `app/src/lib/data/local-adapter.ts` : `remove` (158-162) lit d'abord l'entrée (`getDatabase().rows.get(rowKey(table, { id }))`) ; absente et `ifMissing` différent de `'ignore'` ⇒ lever le même `DataError`, sinon supprimer. `removeWhere` (165-172) compte `targets` ; zéro cible et `ifMissing` différent de `'ignore'` ⇒ lever ; sinon supprimer. Le mode démo doit donc se comporter comme le serveur, faute de quoi le défaut resterait invisible en CI (constat structurel de la phase : Vitest tourne en Dexie, sans RLS).

Créer `app/src/lib/data/remove-contract.test.ts` : c'est la preuve de contrat, et le chemin de bout en bout du tracer. Y mocker `@/lib/supabase/client` (`isSupabaseConfigured: true`, `supabase` = faux client dont le constructeur de requête capture les appels `.from().delete().eq()/.select()` et rend un jeu commandé : zéro ligne, N lignes, ou une erreur) — `@/lib/data` étant le module **réel**, `data` y résout donc vers `SupabaseAdapter`, sans mock de `@/lib/data`. Assertions : zéro ligne ⇒ rejet avec `DataError` ; N lignes ⇒ résolution ; `{ ifMissing: 'ignore' }` ⇒ résolution silencieuse ; erreur du client ⇒ rejet dont le `cause` porte l'erreur d'origine. Puis, dans le même fichier, instancier `getLocalAdapter()` et prouver les mêmes trois cas en mode local (la ligne absente d'un `remove`, la cible absente d'un `removeWhere`). Terminer par un cas de bout en bout sur un consommateur **réel** : importer `removeArdoiseMember` depuis `@/modules/ardoise/api` et l'appeler pour un couple (ardoise, membre) absent — la promesse doit désormais rejeter au lieu de résoudre. C'est le chemin complet contrat → adaptateur → API de module ; aucun autre site d'appel n'est touché ici.

Contrainte de style : aucun bloc de code n'est à recopier, les signatures et clés de configuration sont nommées ci-dessus. Ne pas réécrire `useResource` (il délègue sans option : le défaut strict est celui qu'on veut pour lui).

| Boundary | Description |
|----------|-------------|
| client → PostgREST (DELETE) | Le client envoie une suppression ; la politique `*_delete_admin` décide du nombre de lignes affectées. Le serveur ne lève pas : il n'affecte rien. |
| client → PostgREST (INSERT) | L'adaptateur construit la charge ; injecter une colonne inexistante fait échouer l'insertion, que l'appelant doit voir. |
| migration → schéma | Mesure : les clés composites sont déclarées par la migration, la constante du client doit s'y accorder. |
