<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonyme → `ardoise-invite` | le code d'invitation EST le contrôle d'accès ; la fonction lit avec la clé secrète et ne doit rendre que ce que le lien autorise |
| `ardoise-invite` → Storage | la fonction forge une URL signée courte ; une URL signée est un porteur de droit temporaire, elle ne doit pas survivre à la réponse ni fuiter dans les journaux |
| navigateur déconnecté → `/connexion` | `state.from` est une donnée du navigateur : elle ne doit pas devenir une redirection ouverte |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-41 | Information Disclosure | `resolveGuestCoverUrl` | mitigate | Validité 1 h forgée par requête ; échec fermé à `null` ; la valeur brute n'est jamais journalisée (motif `recipe-invite:439-460`) |
| T-19-42 | Information Disclosure | charge utile invitée | mitigate | La fonction ne rend que la couverture de l'ardoise que le code autorise ; le chemin du bucket ne sort plus vers un anonyme — seule une URL signée courte sort |
| T-19-43 | Elevation of Privilege | `state.from` | mitigate | N'accepter qu'un chemin interne de l'application (préfixe `/`), jamais une URL absolue : sinon la connexion devient une redirection ouverte. Prouvé par un cas de test |
| T-19-44 | Spoofing | `coverUrl` invité | accept | Une URL signée est porteuse : qui la partage la donne. Le rayon est borné par la TTL courte et par le fait que la page invitée est déjà publique par conception |
| T-19-45 | Denial of Service | signature par requête | accept | Une signature par affichage invité ; le bucket est déjà servi ainsi par deux autres fonctions invitées |
